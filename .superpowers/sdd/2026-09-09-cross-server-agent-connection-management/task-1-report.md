# Task 1 Report: Agent Connection Lease Lifecycle

## Implementation

- Added `AgentConnectionLeaseController` to register, renew, update, and release one durable lease per process-local Agent WebSocket.
- Added `NodeRegistry.UpdateConnectionStats` and implemented it for MySQL/SQLite and etcd registries.
- Added `AgentSessionConfig.HeartbeatCallback` and a manager setter so the runtime can refresh cluster leases on Agent heartbeat without coupling the session manager to the registry package.
- Wired the controller into `ServerRuntime` and `serveAgentWS`:
  - register a lease after local session registration succeeds;
  - reject and clean up the WebSocket if lease registration fails;
  - release the exact lease when the Agent read loop exits.
- Added runtime injection for `ConnectionRegistry`, allowing tests and future etcd deployments to provide a registry implementation.
- Defaulted an unset local node identity to `local` to preserve existing local-mode and embedder behavior.

## Self-Review

- The lease epoch generated by `NodeRegistry` is distinct from the protocol connection epoch. The controller stores the registry owner separately; later close tasks must use the registry epoch for lease fencing and the session epoch for local execution.
- The runtime now rejects Agent WebSockets when cluster lease registration fails, matching the design's manageability requirement.
- Heartbeat lease failures are intentionally ignored in the read loop so a transient registry failure does not tear down a healthy forwarding channel.
- The local node ID defaults to `local` when omitted, preserving existing tests and local mode.
